## Задача

Ты фронтенд-разработчик проекта «Норма» (Angular + SCSS, репозиторий
`C:\Users\elina\source\repos\Norma`). Твоя задача - перенести экран из макета
Figma в код, не выдумывая дизайн.

## Что где лежит

| Путь | Что это |
|---|---|
| `design/figma-*.json` | экспорт из Figma, бери последний по дате |
| `web/src/styles/_tokens.scss` | токены, сгенерированные из экспорта |

Источник правды - JSON из Figma. PNG-черновики в `.tmp-preview/` устарели: они
были основой, пока макет не перенесли в Figma. Спорные места решай по JSON.

## Шаг 1. Прочитай макет выборочно

JSON весит около 700 КБ. Не открывай его целиком и не читай через `cat` -
используй готовый скрипт:

```powershell
# список экранов в файле
node tools/figma-plugin/read-nodes.mjs design/figma-<дата>.json

# дерево одного экрана
node tools/figma-plugin/read-nodes.mjs design/figma-<дата>.json --frame "Вес" --depth 3

# переменные и текстовые стили
node tools/figma-plugin/read-nodes.mjs design/figma-<дата>.json --tokens

# частоты цветов, радиусов, кеглей
node tools/figma-plugin/read-nodes.mjs design/figma-<дата>.json --usage

# найти узел по имени или тексту, если не знаешь, в каком он экране
node tools/figma-plugin/read-nodes.mjs design/figma-<дата>.json --search "Талия"
```

Строка дерева выглядит так:

```
TEXT 72,4  49x27  @3500,450  #111827 var(--color-text)  22/700 "72,4"
```

Порядок полей: тип, имя, размер, координаты, радиус, заливка, кегль/вес, текст.

## Шаг 2. Сверь токены

`_tokens.scss` должен быть не старше экспорта. Если экспорт новее - перегенерируй:

```powershell
node tools/figma-plugin/to-scss.mjs design/figma-<дата>.json web/src/styles/_tokens.scss
```

Файл генерируется, руками не правится.

## Шаг 3. Верстай по числам

- **Цвета** - только `var(--color-...)`. Имя переменной в JSON пишется через
  слэш: `color/text-muted` → `--color-text-muted`.
- **Типографика** - `$text-styles` или `$typography` из токенов. Если у узла есть
  `textStyle`, это имя стиля, а не набор чисел.
- **Радиусы и отступы** - `var(--radius-...)` и `var(--space-...)`.
- **Геометрия** - из `size`, `position`, `absolute`. Не округляй на глаз.
- **Отступы без авто-разметки.** Если у узла нет `padding` и `itemSpacing`,
  макет собран абсолютными координатами: считай отступы по разнице координат
  соседних узлов, а поля карточки - как смещение первого ребёнка от её края.
- **Текст** - поле `characters`. Если `truncated: true`, узел обрезан: попроси
  уменьшить выделение и повторить экспорт, а не дорисовывай.

## Шаг 4. Проверь

- Собери проект: `npx ng build` (или сборка стилей, если правились только они).
  Ошибок быть не должно.
- Сверь ключевые числа с макетом: ширина карточки, высота топбара, кегли
  заголовков, цвет текста.

## Правила

- Никаких новых цветов, радиусов и отступов, которых нет в макете. Если
  чего-то не хватает - спроси, а не придумывай.
- Если значение в макете не совпадает с токеном - бери ближайший токен и отметь
  расхождение в отчёте.
- Не править `_tokens.scss` руками.
- Не коммитить без подтверждения.
- Не переписывать соседние компоненты, если задача этого не требует.

## Отчёт

1. Что сверстал: файлы и компоненты.
2. Какие токены использовал.
3. Расхождения с макетом: цвет, размер, отступ - списком.
4. Что требует решения: нет токена, спорный отступ, отсутствует состояние
   (hover, focus, пустой экран).

## Что впереди

Рецепты и создание рецептов, ночной стиль, настройки, аватар, мобильная версия.
Порядок тот же: макет в Figma → экспорт → токены → верстка. Если экрана ещё нет
в экспорте - скажи об этом, а не дорисовывай по памяти.
