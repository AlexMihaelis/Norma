# MindVault — память WorkSpace

Этот файл автоматически загружается DSH в начале каждой сессии с рабочим каталогом
`C:\Users\elina\source\repos\MindVault`. Всё, что здесь написано, агент знает без
напоминаний. Держим его коротким: только устойчивые факты и договорённости.

## Как вести этот файл

- Пользователь говорит «запомни …» / «запиши …» → дописать факт в раздел
  «Факты и решения» с датой (формат `ГГГГ-ММ-ДД`).
- В конце задачи: если появилось устойчивое решение, ограничение или договорённость,
  которое понадобится позже — дописать строку. Разовые детали, логи, переписку и
  секреты сюда не пишем.
- Устаревшее не удалять молча: помечать `(устарело: <причина>)`.
- Файл читается в каждом запросе, поэтому бюджет — примерно 1–2 КБ прозы.
  Разрастается → вынести детали в отдельный `.md` и оставить здесь ссылку.

## О пользователе

- Язык общения — русский; отвечать по-русски, без канцелярита.
- Сильная сторона — backend на C# / .NET. Angular, TypeScript, Tailwind CSS,
  Taiga UI — уровень «пощупать», не основной.
- Хочет получить опыт использования ИИ-агентов как инструмента разработки.
- Хобби: рисование, электрогитара (регулярной практики пока нет).

## Проект

- **Название:** «Норма» (Norma), выбрано 2026-11-16. Каталог пока `MindVault`.
- **Что:** веб-приложение «дневник питания, веса и активности» — питание, вес,
  физическая активность, цели, аналитика прогресса; позже мобильный клиент.
  Автор идеи — пользователь.
- **Статус:** согласовано 2026-11-16, код не начат. Детали, домен, движок, стек,
  шесть задач v1 с критериями приёмки — в [docs/PROJECT.md](docs/PROJECT.md).
- **Граница с NEST** (бытовой органайзер, пользователь делает параллельно руками):
  пересечение только с модулем Recipes, и решено так — рецептов в v1 нет, в v2
  рецепт вычислимый (ингредиенты → КБЖУ), а не текстовая библиотека.
- **Архитектура (решение пользователя):** не CQRS/MediatR — вертикальные срезы
  (папка на сценарий, minimal API) + функциональное ядро `Core` из чистых функций
  без EF/DI/`DateTime.Now`. Причина: NEST уже покрывает Clean Architecture + CQRS,
  в портфолио нужен другой подход, и его проще довести до конца.
- **Стек:** .NET 9 minimal API, PostgreSQL, EF Core, Angular, Docker Compose,
  `/api/v1` с первого дня. Многопользовательское, изоляция данных по `userId`.
  Тесты: юнит на `Core`, интеграционные на WebApplicationFactory + Testcontainers,
  property-based (FsCheck/CsCheck) на генератор меню.
- **Флагман v2:** генератор меню на день/неделю — КБЖУ в коридоре, аллергены
  исключены (fail-closed), разнообразие, минимум докупок; из меню выводится список
  покупок.
- **Сейчас только веб.** Мобильный клиент отложен и обсуждается отдельно; вместе с
  ним отложены фото-распознавание блюд, Health Connect, часы, шаги и сон.
- **Данные:** база продуктов — USDA FoodData Central (CC0), ~400–600 базовых
  ингредиентов, русские названия в отдельной таблице локализации (кураторство, не
  дословный перевод); бренды и штрихкоды — Open Food Facts по требованию через API
  с кэшем и атрибуцией (ODbL); рецепты — 30–50 своих seed-записей, без скрапинга.
- **Вне scope:** ИИ внутри веб-приложения, рецепты и соцфункции в v1, интеграции с
  трекерами, медицинские рекомендации.
