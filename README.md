# Норма (Norma)

Веб-приложение, которое собирает данные о питании, весе и активности в одной
системе и помогает удерживать цель. Ключевая идея — не дневник калорий сам по себе,
а планирование меню под свою норму КБЖУ с отсечением аллергенов и списком покупок.

Полное описание, домен, задачи и критерии приёмки — в [docs/PROJECT.md](docs/PROJECT.md).
Память проекта для ИИ-агентов — в [AGENTS.md](AGENTS.md).

## Стек

- Backend: .NET 9, ASP.NET Core minimal API
- Frontend: Angular + TypeScript (подключается отдельной задачей)
- Хранилище: PostgreSQL, EF Core
- Запуск инфраструктуры: Docker Compose

## Как запустить

```powershell
# база данных
docker compose up -d db

# API (в Development сам применяет недостающие миграции при старте)
dotnet run --project src/Norma.Api
```

В Development схема догоняет миграции прямо на старте: флаг `Database:MigrateOnStartup`
в `appsettings.Development.json`. Если база не поднята, API все равно запускается, а в
лог пишется, что именно сделать. В других окружениях автоматики нет - миграции это
шаг деплоя:

```powershell
dotnet ef database update --project src/Norma.Api
```

`dotnet ef` ставится один раз: `dotnet tool install --global dotnet-ef`. Проверить,
что база догнала: `dotnet ef migrations list --project src/Norma.Api` (у примененных
миграций нет пометки `(Pending)`).

Проверка:

```powershell
curl http://localhost:5xxx/api/v1/health
# {"status":"ok","version":"1.0.0.0"}
```

Точный порт печатает сам `dotnet run` (см. `src/Norma.Api/Properties/launchSettings.json`).

## Тесты

```powershell
dotnet test
```

Интеграционным тестам нужен Docker: они поднимают Postgres через Testcontainers.

## Структура

```
src/Norma.Api/Features/   вертикальные срезы: одна папка = один сценарий
src/Norma.Api/Data/       DbContext, EF-конфигурации, миграции
src/Norma.Api/Jobs/       фоновые задачи (импорт базы продуктов)
src/Norma.Core/           чистые функции расчётов: без EF, без DI, без DateTime.Now
tests/Norma.Core.Tests/   юнит-тесты ядра (миллисекунды)
tests/Norma.Api.Tests/    интеграционные тесты через WebApplicationFactory
```

Правила, которые держат структуру от расползания: срез не вызывает обработчик
другого среза; бизнес-правило живёт в `Core`, а не в эндпоинте; generic-репозиториев
нет — EF Core и есть доступ к данным.

## Статус

Готовы базовые срезы API:

- аутентификация (JWT) и профиль: пол, дата рождения, рост, активность, цель,
  желаемый вес;
- норма калорий по сохраненному профилю и последнему весу;
- вес: запись, история, тренд с датой цели, ИМТ и нормой веса (18.5-25, для 65+ 22-27);
- вода: приемы за день и дневной ориентир;
- активность: запись и день с суммарным расходом;
- дневник питания: запись позиции в прием, день с КБЖУ и итогами, удаление
  позиции, повтор вчерашнего дня; КБЖУ пересчитывается из продукта, единицы -
  граммы и миллилитры;
- избранные продукты: добавить, список и убрать отметку;
- свои продукты: создание продукта с авторством и строгой валидацией;
- статистика за период: дни с записями, средние, отклонение от цели по весу дня;
- поиск продуктов и документация API (`/scalar/v1`).

Ближайшие шаги: фронтенд, история профиля, рецепты (v2).

## Источники данных

- База продуктов: USDA FoodData Central (CC0), русские названия — своя таблица
  локализации.
- Бренды и штрихкоды: Open Food Facts (ODbL), запросы по требованию с кэшем.
  Данные Open Food Facts используются с атрибуцией.
